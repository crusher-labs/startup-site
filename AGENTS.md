# AGENTS.md - startup-site

`startup-site` is a one-off crusher-labs site experiment: a single-page startup landing page.

Workspace rules: `x:\crusher-labs\AGENTS.md`. Global rules: `~/.claude/CLAUDE.md`. This file only adds what is specific to this repo.

## What it is

- **Stack:** Vite 4 + React 18 SPA (JSX, no TypeScript), no router (single page, scroll-to-section nav), styling with Tailwind CSS 3 + Radix UI primitives, animation via Framer Motion, icons via lucide-react, document head via react-helmet. `@/` aliases `./src`.
- **Purpose:** Marketing/landing site for a fictional biotech startup ("Eclipse"). One page composed of Header, Hero, Features, KeyPoints, Solutions, Pricing, Footer sections; the header links scroll to the matching section. Generated by Hostinger Horizons, then scaffolded into the crusher-labs org (single commit "create template").
- **Hosting:** None wired up. No Vercel/Netlify config, no GitHub Pages workflow, no `CNAME`. It builds to a static `dist/` (gitignored); deploy target is undecided. Treat it as a build-only static experiment until a host is added.

No test or lint script is defined. `eslint` is installed but there is no `lint` script or eslint config.

## Conventions

- The `build` script prefixes `node tools/generate-llms.js || true`, but `tools/` does not exist; the `|| true` swallows the failure so `vite build` still runs. The llms-generator step is a no-op today; do not assume it produces anything.
- Leftover boilerplate identity: `package.json` name is `eclipse-app`, `README.md` is just the bare repo name, and `index.html` carries a `Hostinger Horizons` generator meta tag. The real product name in the rendered page is "Eclipse"; treat the scaffold artifacts as non-authoritative.
- Page content lives in section components under `src/components/`; shared shadcn-style primitives live under `src/components/ui/`. The `@/` import alias points at `./src`.

## What NOT to do

- **Do not commit to `main` carelessly.** There is no `dev` branch yet; if you start real feature work, create `dev` from `main` and work there. Docs-only changes on `main` are fine.
- **No `Co-Authored-By` or AI-attribution trailers** in commits or PRs. User identity only.
- **Do not put secrets in tracked files.** `.env*` is gitignored; keep credentials out of the repo.
- Do not commit `dist/` or `node_modules/` (both gitignored).
